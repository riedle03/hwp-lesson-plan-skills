# HWPX 형식 그대로 복제(Format-Faithful Clone)

기존 `.hwpx`의 **편집 형식(표 구조·본문 스타일·페이지 서식)을 한 글자도 새로 만들지 않고 그대로 따서** 새 내용으로 채운다. 이 스킬의 존재 이유: 한글 HWPX 작업은 표 형식·본문 양식을 **한 번에 다 못 가져오고 꼭 한두 개를 놓친다**. 그래서 이 스킬은 (1) 신규 생성 금지·클론 강제, (2) 40+ 항목 형식 체크리스트, (3) **모든 항목 통과까지 자가검증 루프**로 그 누락을 구조적으로 막는다.

## 절대 원칙 (먼저 읽어라)

1. **markdownToHwpx / 새 문서 생성 금지.** kordoc `markdownToHwpx()`는 서식 없는 generic 문서를 만들어 템플릿의 병합셀 헤더표·테두리·폰트·단(컬럼)·페이지 서식을 전혀 재현하지 못한다. **반드시 템플릿 `.hwpx`를 ZIP으로 열어 `Contents/section0.xml`의 본문만 외과적으로 치환**한다.
2. **`Contents/header.xml`·`content.hpf`는 바이트 그대로 보존.** 폰트·문단(줄간격)·테두리(borderFill) 스타일 정의의 원천이다. 손대면 형식이 깨진다. 새 요소는 **템플릿이 쓰는 그 스타일 ID(charPr/paraPr/borderFill)를 그대로 참조**한다.
3. **형식 몰드는 추측하지 말고 템플릿에서 추출**한다. 표·박스·문단의 OWPML 조각을 "예시 텍스트 앵커"로 찾아 잘라내(몰드) 내용만 바꿔 재사용한다.
4. **한글은 저장된 `<hp:linesegarray>`를 그대로 신뢰하고 줄 레이아웃을 재계산하지 않는다(★ 반복 버그의 근원).** 셀·문단에 **한 줄을 넘는 텍스트를 채우면서 `<hp:lineseg>`를 1개만 남기면 한글에서도 한 줄로 욱여넣어져(cram) 셀/페이지 폭을 넘쳐 깨진다.** "한글이 열 때 알아서 줄바꿈/reflow하겠지"는 **거짓**이다(본문 문단·자동확장 셀도 마찬가지). → 채운 **모든** 문단은 글자 디스플레이 폭(한글·전각=2, ASCII·공백=1)으로 줄 수를 계산해 **줄마다 `<hp:lineseg>`를 재생성**하고 셀/표 높이를 줄수에 맞춰 키워야 한다(체크리스트 **D**·레시피 **§4/§5**). rhwp render는 한글과 **동일하게** linesegarray를 따르므로(둘 다 single-lineseg를 cram) **줄바꿈 깨짐을 탐지하는 오라클로 쓸 수 있다** — 레시피 **§8 글자 x좌표 검사**(어떤 글자도 페이지/셀 텍스트 폭을 넘지 않아야 PASS). 단 **쪽 넘김 위치**만은 rhwp로 검증 불가 → 한글 육안.

## 워크플로우 (한 번 호출 → 끝까지 루프)

사용자가 한 번만 요청해도 아래를 **스스로 끝까지** 수행한다. 중간에 사용자에게 "이것도 할까요?"를 묻지 말고, 체크리스트 전 항목을 점검·반영한 뒤 보고한다.

### STEP 0 — 입력 확정
- **템플릿 `.hwpx`** 경로 (형식의 원천). 없으면 사용자에게 요청.
- **새 내용** (md/텍스트). 표·문항·지문 등.
- 메타 치환 목록 (제목·날짜·문항수 등 head 영역 문자열).

### STEP 1 — 템플릿 전수 분석 (★ 누락 방지의 핵심)
`references/01-format-checklist.md`의 **모든 차원을 한 번에** 조사한다. 절대 일부만 보고 시작하지 않는다. 최소:
1. ZIP 엔트리 목록 (`section0.xml`, `header.xml`, `masterpage0.xml`, `content.hpf`, footer/header ctrl 위치).
2. `<hp:secPr>` 페이지 기하: `pagePr`(용지 width/height), `margin`(top/bottom/header/footer/left/right), `colPr`(단 수·간격). → 페이지 용량 계산.
3. **모든 표 종류 열거**: `<hp:tbl>`마다 첫 셀 텍스트·`rowCnt/colCnt`·`borderFillIDRef`·`treatAsChar`·`textWrap`·`pageBreak`·중첩 여부. 각 표가 "무엇을 담는 표"인지 분류(헤더표/선택지표/지문박스/보기노치프레임/내용그리드…).
4. 본문 문단 스타일: 요소 유형별 `paraPrIDRef`·`charPrIDRef` 매핑(제목/지문군 헤더/발문/선택지/지문/저작권/끝표시…).
5. `header.xml`에서 사용 스타일 정의 확인: paraPr 줄간격(%)·정렬, charPr 크기·bold·**underline**(밑줄 charPr가 따로 있는지), fontRef.
6. 특수 장치: 정답 표시(markpen 색), `<보기>` 노치 프레임 구조, 쪽 넘김 안내 문구(본문/꼬리말, 홀짝), 밑줄 span 등 **이 템플릿만의 디테일**.
7. 본문 치환 경계(어디부터 어디까지가 "내용"인지: 예 ※안내 직후 ~ -끝-).

분석 결과를 **표로 정리**해 두고 STEP 2의 몰드 추출·STEP 3 체크리스트의 근거로 쓴다.

### STEP 2 — 몰드 추출 + 본문 생성
- STEP 1에서 분류한 표/박스마다 OWPML 몰드를 추출(앵커 텍스트로 `<hp:tbl>` 잘라내기). 중첩 표(예: 보기 노치 프레임 안의 내용 표)는 **본문 셀 `<hp:subList>` 내용만 치환**하고 프레임은 그대로 둔다.
- 새 내용을 템플릿 스타일 ID로 조판. `references/02-owpml-recipe.md`의 생성기 패턴 사용.
- head 영역 메타 문자열 치환. `header.xml`·`content.hpf`는 그대로 복사. masterpage(러닝헤더)·PrvText도 메타 치환.

### STEP 3 — 자가검증 (체크리스트 게이트)
`references/01-format-checklist.md` 전 항목을 **하나씩** 점검한다. 각 항목 PASS/FAIL 표로 기록. 측정 방법:
- `xml.etree.ElementTree.fromstring`(well-formed) + 표/문단/선택지/정답 카운트 + `<hp:tbl id>` 유일성.
- 템플릿과 `header.xml`·`content.hpf` **바이트 동일성**(md5).
- 사용한 paraPr/charPr ID가 모두 템플릿 정의에 존재하고, 요소 유형별로 템플릿과 동일한지.
- **줄바꿈 cram 게이트(★ 필수)**: 채운 모든 문단에 대해 "텍스트 디스플레이 폭 > lineseg의 horzsize 한 줄 용량인데 `<hp:lineseg>`가 1개"인 경우가 **0건**인지. 있으면 레시피 §4로 다중 lineseg 재생성 + 셀/표 높이 보정. rhwp render→SVG의 글자 x좌표 max가 페이지/셀 텍스트 폭 이내인지로 교차검증(레시피 §8).
- (가능하면) rhwp render→SVG→sharp PNG로 표/박스/단 조판 육안 — **단 페이지네이션(쪽 넘김 위치)만 제외**(나머지 줄바꿈·셀폭은 rhwp가 한글과 동일하게 보여줌).

### STEP 4 — 루프 (FAIL 0까지)
FAIL이 하나라도 있으면 STEP 2로 돌아가 **그 항목만 국소 수정** 후 STEP 3 재점검. 모든 항목 PASS까지 반복. 사용자에게 중간 확인을 받지 않는다(이게 "여러 번 프롬프트" 방지의 핵심).

### STEP 5 — 인계
모든 항목 PASS 후 사용자에게: ① 적용한 형식 차원 요약(PASS 표), ② **한글에서 육안 확인할 항목**(특히 페이지 넘김 위치·표 줄맞춤·밑줄·형광펜 — rhwp로 검증 불가한 것들), ③ 산출물 경로. 검증용 렌더 PNG가 있으면 첨부.

## 양식별 적응 (다른 템플릿)
이 스킬은 **방법론**이다. 새 양식이면 STEP 1에서 그 템플릿의 표·스타일을 새로 분석하고, 앵커(예: 본 예시의 "겹받침"·"기쁨 뒤에 슬픔")를 그 템플릿에 실제 존재하는 텍스트로 바꾼다. 빌드 스크립트(`references/`의 예시)는 그대로 쓰는 게 아니라 **그 템플릿에 맞춰 몰드 앵커·스타일 ID·메타를 조정**한다.

## 트리거 후속
"표 줄이 안 맞아", "밑줄 빠졌어", "보기 헤더 없어", "쪽 넘김 안내 위치", "정답 표시 안 됐어", "다른 양식인데 똑같이" 등 형식 관련 후속도 이 스킬. 매번 한 항목씩 고치지 말고 STEP 3 체크리스트를 **전부** 다시 돌려 한 번에 잡는다.

## 도구 선택 (라우팅 — ★ 먼저 판단)
요청을 받으면 "**무엇을 출력**하고 **얼마나 새로 조판**하나"로 도구를 가른다. 이 스킬(ZIP 클론)은 **양식 100% 보존 + 대량 신규 조판 + `.hwpx` 출력**이 동시에 필요할 때만.

| 하려는 일 | 도구 | 이유 |
|---|---|---|
| 기존 **`.hwp`** 양식에서 **내용 일부만** 바꿈(텍스트 치환·표 셀 채우기), 출력 `.hwp` OK | **`rhwp-edit`** | 제자리 점수정이라 양식 보존·간단. `replace-all`(본문만)·`set-cell-text`(셀 좌표)·`insert-text` |
| HWPX/HWP **읽기·추출**(JSON·md·양식필드·diff) | **`hwp`**(kordoc) | 파싱 강점 |
| 마크다운 → hwpx, **양식 안 따져도 될 때**(백지 생성 허용) | `hwp` markdownToHwpx | 단 기존 양식은 못 따름 |
| 레이아웃 디버깅·IR 덤프·SVG/썸네일 | **`rhwp-advanced`**(Rust CLI) | 읽기·진단 전용(편집·저장 없음) |
| **기존 양식 그대로 + 대량 신규 내용 + `.hwpx` 출력** | **이 스킬(ZIP 클론)** | 셋을 동시에 만족하는 유일한 길 |

**핵심 한계 메모(왜 다른 도구로 양식복제가 안 되나):**
- `rhwp-edit`: **HWPX로 저장 불가(업스트림 #196) → `.hwp`로만 저장**. 점수정 전용(`create-table`은 generic 표). → "내용만 살짝 수정 + .hwp 허용"에만.
- `rhwp-advanced`: **쓰기 명령 자체가 없음**(진단/렌더 전용), Rust `cargo` 필요.
- `hwp`(kordoc) `markdownToHwpx`: **백지에서 새 문서** → 템플릿의 병합셀·테두리·폰트·단 재현 불가.
- → 그래서 "hwpx 출력 + 양식 보존"은 **ZIP 클론 + 본문 XML 치환**만 가능.
