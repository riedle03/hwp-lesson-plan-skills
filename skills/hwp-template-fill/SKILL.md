# 한글 양식 채우기 (Template-Faithful Fill) — 오케스트레이터

기존 양식 파일(`.hwp`/`.hwpx`)을 **틀로 삼아**, 내용만 MD로 완성한 뒤 **표·서식을 한 글자도 안 바꾸고 같은 포맷으로 되채운다.** 매번 양식을 못 따라가거나 포맷이 바뀌는 일을 막기 위해, 이 스킬은 (1) 포맷 자동 판별·엔진 분기, (2) 양식 구조 전수 분석 → MD 매핑 설계, (3) 되채운 뒤 자가검증 루프를 **사용자 재프롬프트 없이 끝까지** 수행한다.

## 철칙
1. **입력 포맷 = 출력 포맷.** `.hwp` 양식이면 최종도 `.hwp`, `.hwpx`면 `.hwpx`. 사용자가 달리 지시하지 않는 한 변환하지 않는다.
2. **양식은 새로 만들지 않고 "있는 것을 채운다".** 표·셀·스타일은 템플릿 것을 보존하고 **내용(칸 텍스트)만** 채운다.
3. **양식 구조를 먼저 전수 파악**한 뒤 MD를 설계한다(나중에 1:1로 들어가도록). 구조 모르고 MD부터 쓰지 않는다.
4. **에이전트는 끝까지 스스로 돈다.** STEP 1~4를 한 번의 요청으로 완주하고, 자가검증에서 누락이 나오면 그 항목만 고쳐 재검증한다.

## 포맷별 엔진 (자동 분기)
| 입력=출력 | 주입 엔진 | 방식 | 강·약점 |
|---|---|---|---|
| **`.hwpx`** | **`hwpx-format-clone` 스킬** | ZIP 클론 + 본문 XML 치환 | 표·서식 100% 보존, 셀 안 리치서식(굵게·밑줄·여러 단락)까지 OWPML로 제어 가능 |
| **`.hwp`** | **`rhwp-edit` 스킬**(k-skill-rhwp) | 제자리 셀 채우기 `set-cell-text`(+`replace-all` 본문) | 변환 없이 .hwp 유지. **단 셀은 텍스트 수준**(셀 안 리치서식 제어 약함), 베타라 복잡표·이미지 round-trip 드물게 손실 |

> `.hwp`인데 **셀 안 서식이 풍부**해야 하면: ① rhwp-edit로 텍스트만 채우고 서식은 한글에서 마무리, 또는 ② 한글에서 `.hwpx`로 저장→클론 주입→`.hwpx`로 작업(이때 최종 포맷이 바뀌므로 사용자 동의 필요). 기본은 입력=출력 유지.

## 워크플로우 (한 번 호출 → 완주)

### STEP 0 — 입력·포맷 확정
- 양식 파일 경로. 확장자로 **포맷 판별**(.hwp/.hwpx) → 출력 포맷·엔진 고정.
- 채울 내용의 소스(있으면) / 없으면 STEP 2에서 함께 작성.

### STEP 1 — 양식 구조 전수 분석 → "양식 맵"
- `hwp`(kordoc)로 파싱: `k-skill-rhwp info`(섹션·문단 수·sourceFormat) + kordoc parse / `list-paragraphs`로 **표·셀 좌표**와 각 칸이 무슨 항목인지 식별. (.hwpx면 raw `section0.xml`도 직접 열어 스타일·표 구조 확인 — `hwpx-format-clone` STEP 1 체크리스트 준용)
- 산출: **양식 맵** = `{셀좌표/문단 → 항목명(단원/학습목표/시간/교수학습활동/자료·유의점/평가…) → 현재값(플레이스홀더)}`. 표가 몇 행몇 열인지, 병합·중첩 표 여부, 칸이 단순 텍스트인지 리치서식인지까지.
- 이 맵으로 **rhwp-edit 충분 여부**(텍스트 칸 위주면 OK)도 판정.

### STEP 2 — MD로 내용 작성 (양식에 매핑되게)
- 양식 맵의 **항목 = MD 섹션/필드**로 1:1 대응되는 MD 골격을 만들어 사용자와 **반복 완성**한다(클로드코드와 함께). 예: `## 학습목표`, `### 1차시 교수학습활동`, 표 항목별 칸.
- MD는 나중에 어느 칸에 들어갈지가 명확해야 한다(셀 좌표 ↔ MD 필드 매핑 표를 유지).

### STEP 3 — 양식에 되채우기 (포맷별 엔진)
- **`.hwpx`** → `hwpx-format-clone`: 템플릿 클론, 해당 셀/문단의 본문만 새 내용으로 치환(표·스타일 보존). 셀 안 리치서식은 OWPML run으로.
- **`.hwp`** → `rhwp-edit`: STEP 1의 셀 좌표로 `set-cell-text`(필요 시 Node API로 반복), 본문 텍스트는 `insert-text`/`replace-all`. 항상 새 파일로 저장(원본 보존).

### STEP 4 — 검증 (자가 루프) + 인계
- 출력 **포맷이 입력과 같은지** 확인(.hwp→.hwp / .hwpx→.hwpx).
- `k-skill-rhwp info`로 재파싱(잘 열림) + 채운 항목 누락/오삽입 점검 + (가능하면) render→PNG로 표·칸 육안.
- **★ 줄바꿈 cram 게이트(반복 버그)**: 한 줄을 넘는 텍스트를 채운 셀·문단은 한글이 `<hp:linesegarray>`를 재계산하지 않으므로, `<hp:lineseg>`가 1개뿐이면 한글에서도 **한 줄로 압축되어 셀/페이지 폭을 넘쳐 깨진다**. `.hwpx`는 "디스플레이폭 > horzsize 한 줄 용량인데 lineseg 1개" 문단 0건 + `k-skill-rhwp render --format svg`의 글자 x좌표 max가 페이지/셀 폭 이내인지 확인(`hwpx-format-clone` 레시피 §4 재생성·§8 검사). FAIL이면 다중 lineseg 재생성 + 셀/표 높이 보정 후 재검증.
- 누락·오류가 있으면 그 칸만 고쳐 재검증(루프). 전부 통과 후 사용자에게: 채운 항목 표·산출물 경로·**한글 육안 확인 권장 항목**(페이지 넘김 등) 보고.

## 한계 (먼저 알리기)
- **`.hwp` 셀 리치서식**(굵게·글머리표·셀 안 여러 단락)은 `set-cell-text`로 완벽 제어가 어려움 → 텍스트 채우고 서식은 한글에서.
- **복잡한 표·이미지·양식필드** 많은 .hwp는 rhwp-edit(베타) round-trip 시 드물게 손실 → 편집 후 렌더 확인.
- **페이지 넘김 등 미세 레이아웃**은 headless로 못 보므로 한글 최종 육안.

## 자율 실행
"질문하지 말고 끝까지 진행해 줘"처럼 맡기면 STEP 1~4를 사용자 확인 없이 완주한다. 중간 산출물(양식 맵·MD)은 작업 폴더에 남겨 사람이 나중에 확인할 수 있게 한다.
